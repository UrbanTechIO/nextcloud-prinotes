# PriNotes To-Do Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a nested-category To-Do section with reminders to the PriNotes Nextcloud web app and Android app, synced like notes, plus configurable Android home-screen widgets.

**Architecture:** New additive tables and REST + sync endpoints on the Nextcloud PHP app; a new Pinia store and views on the web; new Drift tables, sync step, feature folder, local alarms and a native widget on Android. The server owns repeat-spawning so clients never duplicate tasks.

**Tech Stack:** Nextcloud PHP (QBMapper/OCSController, background jobs, notifications), Vue 3 + Pinia + `@nextcloud/axios`, Flutter + Riverpod + Drift + `flutter_local_notifications` + `home_widget` + native Kotlin `AppWidgetProvider`.

**Spec:** `docs/superpowers/specs/2026-11-06-todo-design.md` (read it first; it holds the decisions this plan cites as "spec").

## Global Constraints

- Existing note, notebook, tag, reminder tables, controllers' behaviour and sync results are unchanged. Migration `Version002` is additive only.
- To-do sync failures must never abort note sync (wrap in try/catch like tags).
- Server app version `1.2.0`; Nextcloud 25-35, PHP >= 8.1 (as `info.xml`).
- JSON is camelCase, timestamps are unix seconds, `dueDate` is `YYYY-MM-DD` text with no timezone.
- Repeat rules: `daily | weekdays | weekly | monthly | yearly`. Monthly clamps to month end.
- Category nesting: one level only. Inbox (`isSystem`) is unique per user, not renameable, not deletable.
- Themes: web uses Nextcloud CSS variables (primary `#0082c9`, 12px cards); Android navy `#0F172A`, card `#1E293B`, border `#334155`, primary `#2563EB`.
- Android release builds only. minSdk 31. Never publish, push, tag or release; owner gates that after trying it.
- Server is the production Pi (192.168.0.3). Take a DB dump before the migration. SSH key: `ssh -i ~/.ssh/id_ed25519_pi5`; fall back to the browser Container Terminal (`cterm.urbanstorage.top`) if SSH is unreachable.
- Build sources live in `C:\Users\ramir\Documents\Claude\prinotes` (web/PHP, build tree on Pi `/home/admin/prinotes`, deploy to container `/var/www/html/custom_apps/prinotes`) and `C:\Users\ramir\Documents\Claude\prinotes_flutter` (Android).
- No test framework exists in either project. Verification is by standalone PHP script, `curl` against the live API with an app password, `flutter analyze`, and on-device checks. Do not add phpunit.

## Review Focus

- Monthly repeat on the 31st, or yearly on Feb 29: next date clamps (Jan 31 -> Feb 28/29), never overflows into the next month.
- Task pushed to a category the server already deleted: re-homed to Inbox, not dropped, no error.
- Complete on phone offline (or widget) then edit the same task on web: whole-row higher `version` wins, no duplicate next occurrence, no crash.
- Widget whose chosen category was deleted or renamed: shows an empty state with a "choose again" hint, never crashes or shows another list's tasks.
- To-do endpoint throws (bad data, missing table): `/api/sync/pull` and `/push` still return notes normally.
- Empty or 500+ char title, steps JSON malformed: rejected or trimmed, never a 500 on read.
